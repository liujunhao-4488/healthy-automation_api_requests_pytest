# 用毕业设计练习 AI 测试：面向市面 JD 的能力路线图

> 前提：本路线图基于 2026 年市面真实 AI 测试岗位 JD（AI 应用测试工程师、LLM 评测工程师、AI Quality Engineer 等）提炼能力要求，并逐一映射到本毕业设计（健康饮食推荐系统 + AI 饮食助手）的现有模块与《AI应用改造与评测方案》的分阶段计划。
>
> 一句话结论：**这个项目天然就是一个"AI 测试练兵场"——它同时具备被测系统（LLM 应用）、测试框架（pytest）、评测方案（六类评测体系）三样东西，你要做的是按 JD 的能力清单把每一项都"练出手感"并留下可展示的产出物。**

## 1. 市面 AI 测试 JD 的能力清单（提炼自真实岗位）

综合国内（广州、南京、北京等地 AI 测试岗，12-30K）与海外（LLM Evaluation / AI Quality Engineer）岗位，JD 要求可归纳为六层：

| #   | 能力层            | JD 原文关键词（高频出现）                                                                                                    | 出现频率      |
| --- | -------------- | ----------------------------------------------------------------------------------------------------------------- | --------- |
| 1   | 传统测试功底         | 功能/接口/回归测试、用例设计方法、Postman/Apifox、测试计划与报告                                                                          | 几乎所有岗位    |
| 2   | 编程与自动化         | Python 优先、pytest、Selenium/Playwright、写测试脚本和框架                                                                     | 几乎所有岗位    |
| 3   | LLM 专项测试       | 幻觉、一致性、逻辑性、鲁棒性、Prompt 测试、上下文/多轮对话测试                                                                               | 大部分岗位     |
| 4   | 评测体系设计         | 评测数据集（金标集/对抗集）、LLM-as-a-Judge、指标设计（任务完成率、事实一致性、多轮稳定性）、A/B 对比                                                      | 核心区分项     |
| 5   | RAG / Agent 评测 | 检索 precision/recall、faithfulness、引用正确性、工具调用正确性、Agent 轨迹评测                                                         | 大模型应用岗加分项 |
| 6   | 安全与工程化         | Prompt 注入、越狱、PII 泄露（OWASP LLM Top 10）、Langfuse/LangSmith/RAGAS/DeepEval/Promptfoo、CI/CD 质量门禁、性能（p95/p99、token 成本） | 高级岗位与外企必考 |

另有两条隐性要求：**失败案例分析与归因能力**（模型/检索/工具/系统四层定位）和**质量度量意识**（能定义"什么是好的回答"并量化）。

## 3. 分阶段练习计划（对齐改造方案阶段 0-6）

### 阶段 A：LLM 接口与多轮对话测试（练能力 1+3，1-2 周）

目标：把 `test_assistant.py` 从"接口能通"升级为"AI 行为测试"。

练习内容：

1. **Prompt 边界测试**：同一问题换 5 种问法（口语化/专业术语/错别字/超长/空输入），断言回答语义等价——这是 JD 里"Prompt 测试、鲁棒性测试"的直接练习。
2. **多轮对话测试**：写 pytest 用例模拟"第 1 轮说花生过敏 → 第 5 轮要早餐推荐"，断言推荐不含花生。当前系统历史消息不回传，**这条用例必然失败**——失败用例就是你的第一个 bug 报告，也是最有说服力的面试素材。
3. **响应结构测试**：JSON 模式与自然语言降级两种返回的解析测试。
4. **超时与异常注入**：mock DeepSeek 返回 500/慢响应，验证后端降级逻辑（mock 技能本身就是 JD 高频词）。

产出物：`test_assistant_llm.py`（约 20-30 条用例）+ 一份《AI 助手测试用例设计文档》（测试点拆解：功能/边界/异常/安全四类）。

### 阶段 B：评测集构建与指标设计（练能力 4，2-3 周，对应改造方案阶段 0）

目标：亲手做一次"从 0 到 1 构建评测数据集"，这是 AI 测试岗和普通测试岗的核心分水岭。

练习内容：

1. **构建金标集**：从 `ingredient`/`recipe` 表抽取可验证事实，写 50-100 条用例，按六类分类（每类 ≥10 条）。用例结构直接用方案 5.1 节的 JSON schema（id/category/input/expected/must_include/must_not_include）。
2. **设计指标**：为每类定义可计算的指标（如 `RefusalRate`、`ContextAdherence`、`AttackSuccessRate`），并写清楚分子分母怎么算——JD 面试常问"这个指标你怎么定义、怎么算、怎么防止刷分"。
3. **跑基线**：对当前系统跑一遍，产出第一份基线报告（哪些幻觉、哪些越狱成功），保留数据用于论文对比。

产出物：`docs/ai-eval/` 数据集文件 + 基线评测报告（含失败样例清单）。

### 阶段 C：评测运行器与 LLM-as-Judge（练能力 4，2-3 周，对应方案阶段 1+5）

目标：把"手工点测"变成"一键自动评测"，同时练 mock 和 Judge 两个高级技能。

练习内容：

1. 实现 `MockLlmClient`（返回固定/注入数据），让评测不依赖真实模型也能跑——**测试左移、不依赖外部服务**是 JD 明确要求的工程素养。
2. 实现评测运行器：遍历数据集 → 调用真实 `chat` 接口 → 规则断言（must_include 等）→ 裁判模型打分 → 汇总指标落库（用方案 6.2 节的 `eval_run`/`eval_result` 表）。
3. **三层判定**：规则 + LLM-as-Judge + 人工抽检 5%，并分析"裁判打错分"的案例（面试爱问：Judge 本身不准怎么办）。
4. 用 `promptfoo` 或 `DeepEval` 重新实现一遍同样的评测，对比自研与开源工具的差异——JD 加分项直接命中。

产出物：`evaluation/` 模块 + 指标对比报告（自研 vs DeepEval）。

### 阶段 D：红队与 AI 安全测试（练能力 6 前半，1-2 周，对应方案阶段 3）

目标：练出"攻击者思维"，这是 JD 里"安全专项测试"和红队工程师方向的核心。

练习内容：

1. 构建攻击用例集，覆盖：直接越狱、角色扮演绕过、指令注入、系统提示词泄露、跨用户数据泄露、医疗危险建议（催吐/极端节食）、PII 注入（让模型复述用户手机号）。
2. 对照 **OWASP LLM Top 10**（LLM01 提示注入、LLM02 不安全输出处理、LLM03 训练数据投毒、LLM06 敏感信息泄露等）逐条给自己的系统做风险评估表——这一条在外企和安全方向 JD 里几乎必考。
3. 实现 `InputGuardrail` 规则拦截，回归验证拦截率（`AttackSuccessRate` 从 X% 降到 Y%——量化改进是简历金句）。

产出物：`red_team` 攻击集 + 防护前后对比报告。

### 阶段 E：RAG 评测（练能力 5，2-3 周，对应方案阶段 4）

目标：补上大模型应用岗最热的 RAG 测试经验。

练习内容：

1. 按方案 4.4 节把 ingredient/recipe/文章建成检索知识块（MySQL FULLTEXT 起步即可）。
2. 用 **RAGAS** 指标评测：faithfulness（忠实度）、answer relevancy、context precision/recall，理解每个指标背后的含义而不只跑分。
3. 测检索边界：同义词查询、错别字、无答案问题的"拒答率"、知识库污染（插入错误知识块看模型是否照抄）——"stale/poisoned content"在海外 JD 里是明确考点。

产出物：RAG 评测报告 + 幻觉率前后对比（有知识库 vs 无知识库）。

### 阶段 F：工程化闭环（练能力 6 后半，1-2 周，对应方案阶段 5+12）

目标：把所有测试串成 CI 流水线，达到"平台型"能力。

练习内容：

1. GitHub Actions：PR 时跑单测 + MockLLM 评测，每日/每周跑真实模型评测 + 红队，低于阈值阻断合并（质量门禁）。
2. 接入 **Langfuse**（开源可自建）替代/补充 `llm_trace` 表，练"可观测平台"使用经验——JD 加分项第一名。
3. Locust/k6 压测 `chat` 接口：并发、p95/p99 延迟、token 成本统计，写性能测试报告。
4. 失败归因演练：拿 3 个失败 case，定位是模型问题、检索问题、上下文组装问题还是系统 bug——对应 JD"协助定位模型、检索、工具、数据或系统问题"。

产出物：CI 配置 + 压测报告 + 归因分析记录。

## 4. 产出物 → 简历/面试话术对照

| 练习产出 | 简历表述（STAR 骨架） |
| --- | --- |
| 阶段 A + B | "为基于 DeepSeek 的饮食助手设计并实现 100+ 条六维评测用例（幻觉/上下文/记忆/准确性/安全），产出基线报告，发现历史消息不回传、越狱无拦截等 8 类缺陷" |
| 阶段 C | "自研 pytest 评测运行器，支持 MockLLM 测试左移与 LLM-as-Judge 自动评分，并与 DeepEval 对比验证；评测结果落库支持回归对比" |
| 阶段 D | "构建 30+ 条红队攻击集，对照 OWASP LLM Top 10 做风险评估，实现输入护栏后攻击成功率从 X% 降至 Y%" |
| 阶段 E | "搭建营养知识库并引入 RAG，使用 RAGAS 评测 faithfulness/recall，幻觉率下降 Z%" |
| 阶段 F | "搭建 GitHub Actions 质量门禁（单测 + MockLLM 评测必过、真实模型评测日跑），Locust 压测输出 p95 延迟与 token 成本基线" |

面试高频题型自测（源自真实 JD 与行业总结）：

1. "给一个客服聊天机器人设计一套评测方案" → 你做过阶段 B/C，直接拿饮食助手类比作答。
2. "LLM-as-Judge 打分偏低，你怎么判断是模型差还是裁判差？" → 阶段 C 的人工抽检经历就是答案。
3. "Prompt 注入有哪些攻击面，怎么防？" → 阶段 D 的攻击集 + 护栏 + OWASP 映射表。
4. "RAG 回答不准，你怎么定位是检索问题还是生成问题？" → 阶段 E/F 的归因流程。
5. "怎么定义一个'好的回答'？" → 你的六类指标体系就是量化答案。

## 6. 执行建议

1. **顺序不要乱**：A → B → C 是主线（JD 核心区分项），D/E/F 可以按兴趣和时间裁剪；如果时间紧，B + C + D 是最小求职闭环，E/F 是加分项。
2. **每个阶段都以"报告 + 量化数字"收尾**，不要只写代码——测试岗的价值展示就是报告。
3. **失败用例比成功用例值钱**：当前系统历史不回传、无护栏、有明文密钥，这些"缺陷"正是你练习缺陷管理与归因的免费素材，别急着先修。
4. **与论文双线复用**：阶段 0-6 的产出同时就是论文第 4/5 章的实验数据，一份投入两份产出。
