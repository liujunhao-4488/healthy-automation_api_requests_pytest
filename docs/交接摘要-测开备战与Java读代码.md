## 二、这轮讨论的六个结论

**1. 公司的 AI 测试部分可以参考，但参考的是「口径」不是「代码」**
- 公司那套是「Agent 评测工具」：数据集 → 链路评测（性能）→ 准确性评测（Dify 当裁判）
- 能学：**TTFT 首字耗时**（用服务端事件时间戳算）、**三段耗时拆解**、**LLM-as-Judge 范式**
- 不能做：抄代码、简历写成自己做的、带走业务数据
- 公司那套是「Excel 回合制批处理」，改口径要重跑模型；自己那套是「离线重算，0 成本」——**架构上自己更先进**，这是面试素材

**2. 「高级测开开发占比多」≠ 要学 Java 后端**
- 开发能力分四层：写脚本 → 写工具 → 写框架 → 写平台
- 高层的核心能力是**架构设计 / 系统设计**，不是 Java 语法
- 目标公司技术栈是 Java 时，Java 才是必要载体（判断方法：抓 10 份 JD 看技术栈栏）

**3. 原路径（JavaSE→JavaWeb→MySQL→苍穹外卖）时间账**
- 合计 **370–500 小时**，在职每天 3h 需要 4–5.5 个月
- 一个月只能走 35–40%
- JavaWeb 里 JSP/Servlet 手写这部分，在自己项目里出现 **0 次**

**4. 目标改成「能看懂项目代码」后，工作量差 10 倍**
- 从 370–500h → **30–40h**（每天 2h 约两周半）
- 路径反过来：**从代码入手，缺什么补什么**
- 实测自己项目：76 文件 / 12264 行，`Optional` 0 次、JSP 0 次、手写 JDBC 0 次
- 苍穹外卖定位：当**代码样本**可以翻，当**简历项目**零加分

**5. 读代码卡人不在语法，在框架约定**
- 「对象谁 new 的」「接口怎么找到实现」「JSON 怎么变对象」
- 这三件事教程要讲 20 小时，在自己代码里读一遍 2 小时就通

**6. 起点诊断结果**
- 用 `AuthController` 真实代码问三题，**三题都答不上来**
- 结论：缺的是同一个底层概念（IoC），不是三个知识点
