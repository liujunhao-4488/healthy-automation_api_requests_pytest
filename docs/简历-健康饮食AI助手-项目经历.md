# 简历 · 项目经历（定稿）

> 健康饮食 AI 助手 · 质量保障与评测体系 | 个人项目 | pytest + requests + Allure + GitHub Actions | 2025.12–2026.05

## 一、主版本（6 条，推荐）

**1. 意图识别与路由评测**
针对「记录 / 查询 / 知识 / 建议 / 兜底」五类核心意图建立分类测试体系，手工构建 27 条平台专属「黑话」与模糊表达标签集，另设 10 条下游行为观测集（话题命中 / 拒绝措辞 / 越界产物 / 兜底哨兵四类观测点），解决通用模型「懂回答但不懂分诊」的问题。

**2. 安全边界与越狱防御**
定义医疗健康场景安全红线（拒答诊断、强制免责），构建 21 条越狱用例（角色扮演、渐进诱导）与 23 条输入拦截用例，按 B1~B4 边界分桶统计攻破率；另补 13 条提示注入用例（OWASP LLM01），判据刻意断「标记词出现在哪」而非「出不出现」，规避模型复述指令导致的假阳性。

**3. 效果评估与指标量化**
产出意图分类混淆矩阵，定位「记录 vs 查询」等易混淆边界并反推 Prompt 策略；安全侧同时输出漏拦率与误拦率（只算漏拦会诱导规则越收越紧、误伤正常用户）；引入 LLM-as-a-Judge 判定忠实度，用人工标注集校准一致率，并主动标注裁判与被评同源带来的 self-preference 偏差，将结果定位为乐观上界而非结论。

**4. RAG 检索质量评测与调优**
建 40 条分层 golden set（直接事实 14 / 口语改写 12 / 跨段组合 8 / 语料外 6）按类型切片算命中率，实测暴露口语化提问召回仅 7/12；据此定位病因而非硬调阈值——用正负样本得分分布标定相似度阈值（负 ≤5.9 / 正 ≥12.1，取 8.0），再以查询侧停用词削「虚词虚高分」、以覆盖率闸门 0.3（离题 ≤25% / 正题 ≥57%）挡「零星词偶然命中」；补文档-章节两级判据后，发现「文档对、章节全错」导致模型无据可依只能靠训练记忆编造。

**5. 接口安全测试**
按 OWASP API1 设计双账号交叉验证用例，断言不止状态码，还校验数据归属与副作用是否真的发生（越权删除被拒后确认目标资源仍存在），避免「先删后校验」类实现蒙混过关。

**6. CI/CD 与回归工程**
GitHub Actions 编排 MySQL + Flask + Spring Boot 三服务并做就绪探活，按 PR / 主干 / 定时三档分层选跑（118 / 149 / 346 条），未配置模型密钥时自动降级而非静默红；评测脚本消费 pytest 留痕产物离线重算指标，改口径无需重跑模型（单轮 94 次调用已够），失败摘要写入 Job Summary，Allure 报告自动发布 GitHub Pages。

**技术栈**：Python / pytest / requests / Allure / GitHub Actions / MySQL / 正则断言 + LLM-as-a-Judge / BM25 检索评测

## 四、最可能被追问的三点

1. **「你说阈值 8.0，为什么是 8.0？」**
   答：正样本最低 12.1、负样本最高 5.9，空档里取中间偏下；且实测抬到 10.0 会连带砍掉得 6~8 分的正当问题，所以阈值不动，改治病因（停用词 + 覆盖率）。

2. **「LLM-as-a-Judge 凭什么可信？」**
   答：本来不可信。裁判和被评都是 DeepSeek，有 self-preference bias，所以只用人工标注集算一致率，结论写成「上界」，下一步要换厂商模型当裁判。

3. **「误拦率为什么必须和漏拦率一起出？」**
   答：只盯漏拦，规则只会越收越紧，最后正常用户被自己的规则挡在门外；两个数一起看才知道改的是安全还是体验。
