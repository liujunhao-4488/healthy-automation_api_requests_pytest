## 3. 六个真缺口（按"淘汰力 × 性价比"排序）

### G1 🔴 CI + Mock（同一个缺口，必须一起做）— 1.5 天

**为什么是一个缺口**：真模型要网络、要 key、要花钱、结果不确定 → 进不了 CI → 必须先有 Mock 层。
**现状**：`接口自动化-缺口清单.md` 里 P0-4（无 CI）、P1-3（无 Mock）两条都还挂着，10-23 实测确认。

```
最小闭环 = 1 个 Mock fixture + 1 个 workflow + 3 级门禁
```

**Step 1｜Mock 层（1 天）** — `test_cases/ai_assistant/test_fault_injection.py`，四类故障注入：

| 故障 | 注入方式 | 断什么 |
|---|---|---|
| 超时 | mock 客户端 sleep > 超时阈值 | 是否降级 + `source="error"` + 不抛 500 |
| 上游 500 | mock 返回 500 | 是否如说明"暂时无法回复"而非静默空串 |
| 空响应 | mock 返回 `""` | 是否有兜底文案 |
| 脏 JSON | mock 返回 `{"a":}` | 解析异常是否被捕获 |

顺带把 **RAG 检索也 mock 掉**（固定返回 3 个块）→ 这样"检索"和"生成"可以分开断，是链路归因的基础。

**Step 2｜流水线（半天）** — `.github/workflows/api-test.yml`：
检出 → Python 3.11 → 起被测服务（Mock profile，不连真模型/不连外网）→ pytest（junitxml + allure）→ 门禁脚本 → 上传报告 artifact。

**Step 3｜三级门禁**（这条比流水线本身值钱，见 §5 Q2）：

| 级别 | 规则 | 为什么 |
|---|---|---|
| 一票否决 | 安全类（越狱/拦截/注入）通过率必须 100% | 安全不允许"波动" |
| 回归不退化 | 总通过率 ≥ 阈值，且不得比上次低 3 个点 | LLM 用例天然浮动，只能断趋势 |
| 仅观察 | 耗时 / token 成本 / 覆盖率 | 这些抖一下不该阻断合并 |

### G2 🔴 Agent / MCP / Function Calling — 1.5 天（性价比最高的一枪）

**现状**：`algorithm/`、`backend/src/`、`tools/` 三处实测 grep，**mcp / tool_call / functionCall / agent 全部 0 命中**。
你的 AI 助手是"单轮 RAG 问答"——**不是 Agent**。而 JD 职责 3 整段讲的是 Agent / MCP / Skills。

**你的有利条件**：你已经写过一个 Codex Skill（`health-diet-fullstack`），说明你理解"把能力封装成模型可复用的指令单元"这件事。差的是**没做过工具调用、没写过 MCP server**。

**Step 1｜写一个只读 MCP server（半天）** — 三个 tool，直接套在现有 5000 端口上：

```python
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("health-kb")

@mcp.tool()
def search_kb(query: str, source_type: str = "authority", top_k: int = 5) -> list[dict]:
    """检索卫健委食养指南知识块"""
    ...

@mcp.tool()
def lookup_ingredient(name: str) -> dict:
    """按名称查食材营养成分"""
    ...

@mcp.tool()
def recommend_recipes(goal: str, exclude: list[str] = []) -> list[dict]:
    """按饮食目标推荐食谱，可排除过敏食材"""
    ...
```

跑通"Claude Code / Codex 连上它并真实调用一次"就算完成。产出物：`mcp_server/` + 一张调用截图 + 三段话（为什么选这三个 tool、为什么只读、tool 粒度怎么定）。

**Step 2｜把助手改成 2-tool Agent 并写轨迹评测（1 天）** — 这才是你评测能力的落点：

| 断什么 | 怎么断 |
|---|---|
| tool 选择正确率 | 期望 `lookup_ingredient` 的问题，实际调没调 |
| 参数正确率 | 抽出的食材名/目标是否等于人工标注 |
| 步数效率 | 有没有绕圈重复调用同一个 tool（>3 步判失败） |
| 终止正确 | 拿到 tool 结果后是否真的用它作答，而不是丢下结果自己编 |
| 失败路径 | tool 报错时是否如实说"查不到"而非幻觉补全 |

⭐ **这条是你最独特的面试素材**：市面上做"LLM 应用测试"的人多，能说清"Agent 轨迹怎么断"的人少。

### G3 🟡 性能测试 — 半天

**现状**：`latency_report.py` 只统计单请求耗时，无并发/无分位/无瓶颈定位。JD 职责 1 点名"性能测试"。
**注意**：LLM 场景的性能指标和传统接口不一样，**TTFT（首字延迟）才是主指标**，不是总耗时。

用 Locust 打两个接口：
1. `POST /assistant/chat/stream`（SSE）→ **TTFT p50/p95/p99**、首字后吐字速率、token/s、并发 10/50 下错误率
2. `GET /recipe/list`（普通接口）→ 对照基线，用来证明"流式接口的瓶颈在模型侧不在 Java 侧"

产出：一页压测报告 + 一句结论（"并发 50 时 p95 从 X 涨到 Y，瓶颈在 DeepSeek 侧不在应用侧，因为非 AI 接口 P95 几乎不变"）。**这句归因比数字值钱。**

### G5 🟡 Embedding / 向量数据库 — 半天（把"没做过"改写成"比过之后选的"）

**现状**：`kb_retriever.py` 第 25~33 行已写明**故意不用向量库**的三条理由（1500 块规模、可测性、确定性），还写了"换向量只需改 tokenize 一处"的消融设计。**这个理由站得住，是加分项。**

**风险**：JD 要求 5 点名 `Embedding、向量数据库`。他能答"为什么不用"，答不了"向量检索的 recall@k 怎么测、HNSW 参数影响什么"。

**补法**：不重写检索，做**一次消融实验**——加一条 embedding 通道（sentence-transformers 或 API embedding），和 BM25 跑**同一份 golden set**（13 正 + 2 负），比 recall@5 / MRR。

产出：一页对比 + 结论。这样你的说法从"我没做过向量库"变成"**我做过 A/B，在我的规模和可测性约束下 BM25 更优**"——同一个事实，两种身份。

### G6 🟡 "业务抽象与建模"没被表达出来 — 半天

**要求 4 原文**："将复杂业务场景分解为清晰的问题定义、假设与验证路径"。
**你的现状**：能力很强（六工位、五能力线、指标分子分母、防刷分、三种假绿），但**全锁在项目 docs 里，没有变成"给我一个陌生业务我也能拆"的方法论**。面试大概率给一个陌生产品现场拆（"给酒店搜索做质量保障你会怎么开始"）。

**把已有东西抽象成四步法**（一页纸）：

| 步 | 动作 | 你项目里的原型 |
|---|---|---|
| 1 场景切分 | 用户旅程切成 N 个"工位"，每个工位一个独立风险 | 六工位（意图/输入安全/上下文/准确性/输出安全/边界） |
| 2 风险面 | 每个工位列"会怎么坏"，而不是"要测什么" | 幻觉 / 拒答 / 越权 / 注入 |
| 3 可计算指标 | 每个风险面一个分子分母明确的指标 | 漏拦率、误拦率、攻破率、召回率 |
| 4 最小验证路径 | 用最便宜的那层先证伪 | 先离线算指标，再真跑模型 |

然后拿 **2 个陌生产品**各练一次（去哪儿酒店搜索 / AI 客服），写成 2 页纸。这一步零代码，但直接决定面试第二轮的印象。

## 6. 必被问的 7 题（附答法）

1. **"你怎么保证测试本身可信？"**
   → 三种假绿：① 被硬拦吃掉（样本根本没测到模型）② 样本与判据同源（测的是关键词表全不全）③ 断言本身不稳（temperature）。对应三个对策：哨兵断言 `source != blocked`、期望值外置 yaml + nodeid join、只断确定性信号。
2. **"框架和平台差在哪？"**
   → 框架解决"怎么写用例"，平台解决"谁在什么时候跑、跑完谁看、坏了谁负责"：调度、环境编排、结果沉淀与趋势、失败归因、门禁。**"我只做到框架层，平台层的调度和看板是我下一步要补的"**——诚实比硬吹强。
3. **"MCP 是什么？你写过吗？"**
   → 一句话：把工具能力用标准协议暴露给模型，让任意客户端复用，不用为每个模型重写插件。我写过 3 个只读 tool（检索/食材/推荐），刻意只读是因为写操作要额外解决幂等与鉴权。
4. **"Agent 怎么做测试？"**
   → Agent 的"对错"是多维的：结果对不对只是最后一维，前面还有 选没选对 tool / 参数对不对 / 步数有没有绕圈 / 拿到结果有没有真的用。所以断"轨迹"不断"文本"，并用 mock tool 注入错误返回测失败路径。
5. **"RAG 为什么不用向量库？"**
   → 规模 1500 块时向量召回提升接近零；更要紧的是**可测性**——我要测的正是召回，框架会把"为什么召回这块"藏进黑盒。我留了消融口（只改 tokenize 一处即可换向量），并做过 A/B 对比 recall@5。
6. **"给你一个陌生产品，你怎么开始？"**
   → 四步法（场景切分 → 风险面 → 可计算指标 → 最小验证路径），举酒店搜索为例现场拆。
7. **"AI 写的代码你敢用吗？出过什么事？"**
   → ⭐ **必须准备一个"AI 写错、被你抓住"的具体案例**（从你那 11 个缺陷里挑一个）。这条的分数全在这个案例上，不在"我用得很溜"上。
