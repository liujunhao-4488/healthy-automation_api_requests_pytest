# AI 助手模块 · 测试成本估算

> 日期：2026-10-14 ｜ 口径：全量跑一次（178 条，其中 AI 助手 106 条）会花多少钱

## 一句话结论

全量跑一次 ≈ **91 次模型调用**，按 DeepSeek 现行价格 **约 ¥0.2 ~ ¥0.6（不到一块钱）**。

**成本可忽略 —— 不值得为省钱去做 mock 或改后端。**

---

## 一、计价依据

模型：`deepseek-chat`（= deepseek-v4-flash 的非思考模式），配置见
`RecipeServiceImpl` 的 `@Value("${deepseek.model:deepseek-chat}")`。

⚠️ DeepSeek 现行**峰谷定价**，且 2026-08 有过一轮调价，不同来源口径略有差异，故取区间：

| 计费项 | 单价（元 / 百万 tokens） |
|---|---|
| 输入（缓存未命中） | ¥1 ~ ¥1.6 |
| 输入（缓存命中） | ¥0.02 ~ ¥0.05 |
| 输出 | ¥2 ~ ¥4.7 |
| 高峰时段 | 上述价格 × 2 |

> 高峰时段 = 北京时间 9:00–12:00 / 14:00–18:00（其余为平时）。
> 官方价格页会变，实际以 https://api-docs.deepseek.com/zh-cn/quick_start/pricing 为准。

## 二、单次调用的 token 估算

后端每次发给模型的内容（`buildAssistantRequestBody`）：

| 组成 | 估算 |
|---|---|
| system 提示词（`buildIngredientAssistantSystemPrompt`） | ~640 字 |
| 用户上下文（健康档案 / 饮食偏好 / 饮食目标） | ~250 字 |
| 本轮用户提问（`buildIngredientAssistantNaturalUserPrompt`） | ~380 字 |
| **输入合计** | **~1265 中文字 ≈ 1300 tokens** |
| 输出（模型回答） | ~300–400 tokens |

> 多轮样本（越狱的 3 轮、意图标签的"不变量"重问）含历史消息，输入更高，但这类占比很小。

→ **单次调用 ≈ ¥0.002 ~ ¥0.0035**（缓存未命中、平时）。

## 四、成本区间

| 情形 | 全量一次 |
|---|---|
| 乐观（缓存命中率高 / 回答短 / 平时） | ~¥0.15 |
| 中位（本表口径 / 平时） | **~¥0.25** |
| 悲观（高峰时段 + 回答偏长） | ~¥0.6 |

**结论：无论哪种口径，都在"一块钱以内"。**

## 五、为什么"意图标签不调模型省钱"是个伪命题

1. **意图本身不花钱** —— 它是本地关键词算的（`classifyIntent`），调用模型之前就跑完了。
2. **但测试走的端点会调模型** —— `/assistant/chat` 的顺序是"算意图 → 查硬拦 →（没被拦）调模型生成回答 → 一起返回"。非兜底意图**一定调模型**，测试侧选不了。
3. **想真省只能改后端** —— 加一个"只判意图、不生成回答"的轻量端点，或测试侧 mock。
   前者背离"测真实链路"，后者违背"断言期望值来自实测"的铁律 —— **都不划算**。
4. **总量本来就不大** —— 91 次里，意图标签 25 次、越狱 27 次，两边差不多，并不存在一个"费钱大户"值得单独优化。

## 六、附：哪些用例**不**调模型（成本为 0）

- 结构鉴权：无 token 401、空内容 400、不存在的会话 400
- 安全拦截：命中硬拦的 10 条（辱骂 2 + 高危医疗 2 + 越界 5 + 超长 1）
- 意图标签：3 条兜底样本（医疗 / 越界）
- 意图识别：订机票 / 问天气（硬拦）+ 越界-写代码（硬拦）×5
- 流式：`SAMPLE_BLOCKED`（订机票）相关的 3 条

## 七、跑法纪律：怎么跑才不烧钱（★ 最实用的一节）

> 起因：2026-10-14 用户反馈「让你改了代码你就全量跑一次，一天掉了 1000 多次接口」。
> **单次全量不贵（≈¥0.25），贵的是"改一行就重跑一遍全量"这个习惯。**

### 7.1 核心规矩：改什么 → 跑什么

| 我改了什么 | 该跑什么 | 模型调用 | 约花 |
|---|---|---|---|
| 某个 AI 测试文件（如 `test_assistant_意图标签.py`） | **只跑这个文件** | 4~25 | ¥0.01~0.09 |
| 某个非 AI 测试文件（user / diet / auth …） | 只跑这个文件 | **0** | **¥0** |
| 公共件 `conftest.py` / `api/` / `common/` / `config/` | 全量（影响面大） | ~91 | ¥0.2~0.6 |
| 后端 Java 源码 | 全量 | ~91 | ¥0.2~0.6 |
| **什么都没改，只想复跑上次失败的** | `--lf` | 0 ~ 几条 | ≈¥0 |
| 只想看清单 / 确认收集数 | `--collect-only` | **0** | **¥0** |

**一句话：常态是"按文件跑"，全量只在一轮改动的最后跑一次。**

### 7.2 现成命令（README §四 里也有）

```bash
cd D:\jiankang\healthy\automation_api_requests_pytest

# ① 最常用：只跑改动的那个文件（省钱主入口）
python -m pytest test_cases/ai_assistant/test_assistant_意图标签.py -q

# ② 只跑某个目录（比全量小，比单文件大）
python -m pytest test_cases/ai_assistant -q

# ③ 复跑上次失败的（几乎不花钱）
python -m pytest test_cases/ai_assistant --lf -q

# ④ 只看有哪些用例、不执行（0 成本）
python -m pytest test_cases --collect-only -q

# ⑤ 遇到第一条失败就停（省掉后面那一串调用）
python -m pytest test_cases/ai_assistant -x -q

# ⑥ 兜底 runner（本机抓不到 stdout 时用；不带参数时默认只跑 ai_assistant）
python tools/run_tests.py test_cases/ai_assistant/test_assistant_安全拦截.py
```

### 7.3 三条反面清单（这些别再干）

1. ❌ **改一行测试跑一次全量** —— 用 ①，改哪个文件跑哪个文件。
2. ❌ **同一轮里全量跑两遍**（跑完再"确认一下"） —— 全量一轮**一次**就够。
3. ❌ **凭"上次的结论"复用后端状态** —— 跑之前先探活 8080；后端中途死了的那次结果**作废**（否则白花的钱比省的多）。

### 7.4 顺带：想再省就砍 `repeat`（但要先问用户）

真要压调用量，唯一"不伤测试有效性"的旋钮是**多轮/重复采样的条数**：
`test_assistant_越狱.py` 里有 `repeat: 5` 的样本、`test_assistant_意图识别.py` 有 `pass^5` 的两组 ——
**这些是稳定性/概率断言，砍了就削弱结论**，属"用户拍板"范畴，**不要擅自改**。
