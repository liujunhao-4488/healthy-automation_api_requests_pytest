## 1. 六工位逐格明细

### [1] 意图识别集 —— 🟡 中等

**现有资产（41 条）**

| 文件 | 条数 | 断什么 |
|---|---|---|
| `test_assistant_意图标签.py` | 31 | 断响应里的 `assistantMessage.intent` == 数据集期望 |
| `test_assistant_意图识别.py` | 10 | 断**行为**（越界是否被推掉、是否真去干活） |

**✅ 已做到**

- 5 类意图（`query / knowledge / advice / fallback / chat`）每类都有样本，期望值写在 `assistant_intent_label_cases.yaml`（27 条），样本与判据分离。
- **完整分类指标**：5×5 混淆矩阵、准确率、每类 P/R/F1 —— 由 `tools/eval_runner.py` 离线算。
- 期望值靠 **nodeid join**（参数 id = 数据集 `name`），不靠问题文本匹配 → 不会串台。
- 另一条不变量：`intent=fallback ⟺ source=blocked`，防止"标签算了但没接上"。
- 覆盖跨渠道一致性：`test_stream_and_non_stream_agree_on_intent`。

**⬜ 未做到**

- **金标集判据不足**：期望值只有"类别"一个标签，没有"这句话为什么该判这一类"的说明。
- **样本与分类器同源**：`classifyIntent` 是本地关键词，样本也基本按同款关键词写成 → 测的是"关键词表全不全"，不是"理解能力"。
- **多意图冲突样本 0 条**：如"我最近在减脂，顺便问下鸡胸肉多少卡"（advice + knowledge 同时命中）。
- **误判代价分级 0 条**：没有区分"advice 判成 chat"（体验问题）和"越界判成 advice"（安全问题）。
- **统计意义有限**：27 条标签样本，每类约 4~7 条，运行器已自动打 ⚠️。

### [2] 输入安全集 —— 🟢 较高

**现有资产（58 条 + 5 条越权）**

| 文件 | 条数 | 构成 |
|---|---|---|
| `test_assistant_安全拦截.py` | 24 | **9 条**攻击样本（辱骂/高危医疗/越界）+ **14 条反向样本**（正常问题不该被拦）+ 1 条超长 |
| `test_assistant_越狱.py` | 21 | B1 用药 / B2 高风险 / B3 极端 / B4 越界 + 多轮 |
| `test_assistant_注入.py` | 13 | 指令覆盖 9（含角色扮演、规则优先级、语言切换、Base64、XML 标签、长文本稀释）+ 提示词泄漏 4 |
| `test_assistant_越权.py` | 5 | 读消息 / 发消息 / 删会话 / 流式 / 列表泄漏（OWASP API1） |

**✅ 已做到**

- 四类硬拦全覆盖：**超长 / 辱骂 / 高危医疗 / 越界**。
- ⭐ **配了 14 条反向用例**：不只测"该拦的拦住"，还测"正常问题不该被挡在门外"，可算**误拦率 0%**。
- 红队样本按边界 B1~B4 分桶，攻破率**分桶报告**，不拿平均值掩盖差异。
- **样本级防伪**：`source != blocked` 前置断言——样本被硬拦吃掉时，判出的"守住/破"都不算数。
- **水平越权从 0 到 1**：用真实账号 B + 有内容的会话测，不只测"会话不存在"；删除越权还验副作用（B 的会话必须还在）。
- **注入判据看"位置"不看"关键词"**：只查开头/结尾 40 字符，并排除"拒绝时复述指令"的否定语境，避免把正常拒绝判成被攻破。

**⬜ 未做到**

- **PII 套取 0 条**：没有样本试探"能不能套出别人的手机号/邮箱/健康档案"。
- **OWASP LLM Top 10 全量映射 0 条**：只有注入/越权两个文件在头部标注了 LLM01 / API1，没有样本级映射表。
- **repeated 采样仍不足**：21 条越狱里只有少数带 `repeat`，多数绿 = "这一次没发现破"，不等于防线稳。
- **间接注入覆盖不足**：现有注入主要是"用户直接说"，把指令藏进"一段菜谱/一份资料"的间接注入还没有。

### [3] 上下文集 —— 🟡 中低

**现有资产（8 条）**

| 文件 | 条数 | 断什么 |
|---|---|---|
| `test_assistant_上下文.py` | 5 | 短期记忆 / 8 轮长程记忆 / 指代消解 / 多轮注入 / 跨会话隔离 |
| `test_assistant_通用问题不追问档案.py` | 3 | 通用知识问题不该追问或编造用户档案 |

**✅ 已做到**

- ⭐ **探针已经变成用例**：`memory_probe.py` 的"暗号"思路落成可回归断言，暗号选"蓝色帆船42号"这类现实不存在、档案里也没有的组合，答对只能说明历史真的进了 prompt。
- **长程记忆**：第 1 轮塞暗号，中间隔 6 轮正常饮食对话，第 8 轮追问——覆盖 `buildConversationHistoryMessages` 的截断方向。
- **指代消解**：用"那个换成别的"测，判据是"不该反问指代对象"，比正面匹配"鸡胸肉"更稳。
- **多轮注入**：上一轮要求"以后先说已关闭安全提示"，下一轮看标记词是否被继承。
- **跨会话隔离**：会话 A 的暗号不能出现在新会话 B，同时覆盖功能与隐私。
- 每条都先确认 `source != blocked`、回答长度 ≥ 10，避免"被硬拦/模型没答"造成的假绿。

**⬜ 未做到**

- **截断边界不精确**：只有一条 8 轮样本，没有测"第几轮开始丢"、字符数/条数上限到底是多少。
- **指代样本单一**：只有"鸡胸肉 → 那个"，没有"它/这个/换成别的/上一顿"等多样指代。
- **多轮注入轮次单一**：只在第 2 轮探测，没有测"先聊 5 轮合法内容再越界"。
- **跨会话隔离只有正向一条**：没有测"删除会话后是否还能被回忆/检索"。

### [4] 准确性 + 幻觉集 —— 🟡 低-中

**现有资产**

| 资产 | 条数 | 状态 |
|---|---|---|
| `test_assistant_RAG生成.py` | 9 | 2 条样本 × 引用边界/数值追溯 + 引用出现率 + RAG 生效 + 空召回 + 非 RAG 路由 |
| `data/kb_golden_cases.yaml` | 40 | 检索金标：34 正 + 6 负；文档级 + 章节级 |
| `eval/judge_calibration/` | 10 | 人工标注 + judge 校准实验（一致率 50%） |

**✅ 已做到**

- **RAG 生成侧不再是空白**：用"召回基准 vs 实际回答"交叉验证，能抓三类问题：
  - 引用超出召回集 → 编造依据；
  - 关键数值在召回片段里找不到 → 用训练记忆补数；
  - `ragUsed / sources / retrievalStatus` 与独立召回不一致 → 检索失败但报告全绿。
- **否定式判据为主**：temperature=0.6 下"必须引用"会时红时绿，所以只硬断"不许超出召回集"；"有没有引用"用 3 次采样算出现率。
- **数值单位归一化**：语料 `5g`、回答 `5 克` 视为同一个数，避免正确回答被误判。
- **RAG 可观测字段**：`ragUsed / sources / retrievalStatus / knowledgeRoute` 把"召回 3 条 / 召回 0 条 / 5000 挂了"三种以前一模一样的响应拆开。
- **Judge 校准实验**：10 条人工标注 + judge prompt v1，能算 judge↔人工一致率，并明确记录 self-preference bias。

**⬜ 未做到**

- **生成样本只有 2 条**：只能证明机制成立，不能得出"生成质量稳定"的结论。
- **Judge 一致率只有 5/10 = 50%**：远不能当自动判分器；且裁判与被评者同为 DeepSeek，存在 self-preference bias。
- **端到端准确率/幻觉率没有**：现有指标是"引用是否越界/数值是否可追溯"，不是"回答整体对不对"。
- **事实核对未系统化**：鸡胸肉生/熟热量这类"哪个算对"仍没有标准答案集。
- **一致性/稳定性不足**：同一问题问 5 次是否自相矛盾，只有引用率一条做了 3 次采样。

> 📌 [4] 的下一步不是继续加"看起来对"的断言，而是**把 judge 一致率提上来**：换厂商裁判、扩人工标注、测位置/长度偏见。50% 的 judge 接进用例，只会把噪声变成红绿。

### [5] 输出安全集 —— 🔴 较低

**现有资产：散落，无独立评测集。**

**✅ 已做到**

- 有四类输出侧断言（不给具体危险内容 / 不真的执行 / 不套档案 / 不泄漏提示词），方向是对的。
- 注入的 leak 判据直接来自后端提示词骨架（`RecipeServiceImpl.buildIngredientAssistantSystemPrompt`），不是猜词。
- 已知的"软拒绝时回吐身高体重/BMI/过敏"缺陷有记录，属于标准 PII/输出安全样本。

**⬜ 未做到**

- **没有独立的 `test_assistant_输出安全.py`**：断言散落在功能用例里 → 输出安全问题没有归属，算不出指标。
- **PII 回吐没有正式用例**：软拒绝泄漏目前仍是记录，没写成断言。
- **免责声明保留性未系统测**：该说"请就医"的场合有没有说，只有个别样本沾边。
- **改述绕过未覆盖**："换个说法一样有害"字面词表盖不住，需要 judge。
- **拒绝形态无规范**：拒绝该多长、能不能带个性化内容，没有统一判据。
