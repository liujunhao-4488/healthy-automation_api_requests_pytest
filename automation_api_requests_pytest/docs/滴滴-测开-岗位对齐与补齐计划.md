## 2. 三个真缺口（按淘汰力排序）

### 缺口 1：数据结构与算法 —— 唯一"简历救不回来"的

校招测开笔试 = 20 道选择（计网/操作系统/数据库/测试基础）+ 2~3 道编程。你不缺选择，缺编程。

**8 天 40 题清单**（LeetCode 热题 100 里挑，按出现频率排，不要刷难题）：

| 天 | 主题 | 题数 |
|---|---|---|
| D1–2 | 数组 / 字符串 / 哈希表 | 12 |
| D3 | 双指针 / 滑动窗口 | 6 |
| D4 | 栈 / 队列 | 5 |
| D5 | 链表（反转、合并、环） | 6 |
| D6 | 二叉树（遍历、深度、层序） | 6 |
| D7 | 简单 DP（爬楼梯、最大子序和）+ 排序 | 5 |
| D8 | 回刷错题 + 计时模拟 2 套 | — |

**判据**：每道题**先自己写 20 分钟，再看题解**；写完合上题解手打一遍。目标是"认得出来 + 写得对"，不是"会解所有题"。

### 缺口 2：CI/CD + Mock（其实是同一个缺口）

你自己的面试稿 Q23 早就写清楚了这个逻辑：**"要进 CI 得先做 Mock 层——真模型要网络、要 key、要花钱、结果不确定"**。你只是没动手。

所以补 CI 的真实工作量是：**Mock 层（1 天）+ 流水线（半天）**。

```
.github/workflows/api-test.yml
────────────────────────────────
on: [push, pull_request]
jobs:
  api-test:
    runs-on: ubuntu-latest
    steps:
      - 检出代码
      - 装 Python 3.11 + pip install -r requirements.txt
      - 起被测服务（用 Mock profile，不连真模型、不连外网）
      - pytest test_cases --junitxml=reports/junit.xml \
                         --alluredir=reports/allure-results
      - 跑门禁脚本：
          硬门禁  安全类用例通过率必须 100%（否则 exit 1）
          回归门禁 总通过率 ≥ 95%，且不得比上次低 3 个点
          观察项  耗时 / 覆盖率只出报告，不阻断
      - 上传 Allure 报告为 artifact
```

**门禁必须分层**（这条是 JD 第 3 条的考点，也是你 Q20 的原答案）：一票否决 / 回归不退化 / 只观察不阻断。能说出"为什么门禁不能一刀切"比跑通流水线更值钱。

### 缺口 3：把 AI 从"被测对象"翻成"我的工具"

你现在的所有 AI 叙事都是**"我测了一个 AI 助手"**；JD 要的是**"我用 AI 做测试"**。这是角色翻转，不是能力缺失。

**半天小实验（做完就有数字可写）**：
1. 取 `api/` 里的接口 docstring + 覆盖矩阵，喂给 LLM，让它按等价类/边界值生成用例。
2. 你逐条评审：**能直接跑的 / 改一改能跑的 / 完全是废话** → 算出**可执行率**。
3. 和人工已写的用例比对重合度 → 算出**新增价值**（AI 补了哪几个边界是你漏的）。
4. 结论一句话："AI 生成 40 条，可直接采纳 26 条（65%），补出 4 个我漏掉的边界；但**没有一条能直接用，都要人工改**。"

最后半句最重要 —— 它证明你**不迷信 AI**，而这恰好是"应届生别太依赖 AI"那个话题的正解。

### 缺口 4（半天）：LLM 原理层

你缺的不是"AI 风险"，是**原理到测试的因果链**。只需能答清三句话：

- **temperature 高 → 同一条用例跑 5 次结果不同** → 所以断言只能断确定性信号（意图类别、有没有被拦），不能断文本细节。这正是你 `latency_report` 不写成 assert 的原因。
- **上下文窗口有限 → 多轮对话到第 N 轮会"忘"** → 所以上下文测试要测"第几轮开始退化"，而不是"多轮能不能聊"。
- **token 计费/截断 → 超长输入会被静默截断** → 所以要有超长输入用例（你已有）。

## 4. 这个 JD 专用的简历 bullet（草稿，直接用）

> **接口自动化测试框架 + CI 质量门禁** ｜ 个人项目 ｜ 2026.09–至今
>
> - 基于 Python + pytest + requests 搭建三层接口自动化框架（用例 / 接口封装 / 底座），覆盖 **15 个接口、345 条用例**（其中 AI 助手 **221 条**）；接口路径单点收敛，同一路径原散落 17 处、改动成本降至 1 处；数据驱动支持 yaml / json / csv / xlsx 四种格式统一收口。
> - **CI 质量门禁**：GitHub Actions 接入 pytest + Allure，并用 Mock 层替换外部模型依赖，使流水线可**离线、确定性、零成本**运行；按「安全类用例 100% 通过 / 回归通过率不退化 3 个点 / 耗时仅观察」设**三级门禁**，PR 自动产出失败清单与趋势报告。
> - **AI 辅助测试**：以接口文档为输入让 LLM 生成边界与异常用例，用「可执行率 + 与人工用例重合度」评估生成质量，人工评审后采纳 **X%**，补出 **N** 个人工遗漏的边界；结论是 **AI 能提效但不能直接交付**，所有生成用例均需人工评审。
> - **测试数据生成**：笛卡尔积 + 边界算法 + 可复现 fuzz 批量造数，配合 MySQL 事务回滚保证用例跑完零残留。
> - **缺陷发现与回归**：累计发现 **11 个**接口缺陷（6 个已修复并回归验证、2 个用 `xfail(strict=True)` 固化守卫）；覆盖越权访问 4 个入口、JWT 三类篡改、字段白名单、并发唯一性。

> ⚠️ 把 X / N 填成真实数字后再投。**没有数字的"AI 辅助测试"这条不如不写。**

## 6. 这个 JD 特有、一定会被问的 5 题

1. **"你说把 AI 嵌进质量门禁，具体长什么样？"** → 三级门禁 + Mock 兜底（一票否决 / 回归不退化 / 仅观察）。
2. **"AI 生成的用例你怎么保证质量？"** → 可执行率、与人工重合度、人工评审、跑一遍看断言是否真能抓问题。
3. **"智能回归选型你会怎么做？"** → 代码改动 → 影响面分析（接口依赖图 / 调用链）→ 只跑受影响子集；**主要风险是"漏选"**，所以要有"全量兜底周跑"。
4. **"企业级产品和你的个人项目有什么不同？"** → 多租户与权限矩阵、数据隔离、灰度与回滚、历史数据兼容、并发与幂等。
5. **"你用过 AI 写测试，怎么防止自己被它带偏？"** → ⭐ 用你的"三种假绿"（被硬拦吃掉 / 样本与判据同源 / 断言本身不稳）来答，这是你最硬的差异化。
